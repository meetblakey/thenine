# Data Models

## Database Defaults

Database: Aurora PostgreSQL 16 with PostGIS. Primary keys use UUIDv7 generated by the API. All timestamps are `timestamptz` in UTC. Soft deletion uses `deleted_at` only when historical audit, safety, payment, or conversation integrity requires retained rows.

No dating inventory table is keyed by `member_id` as the recipient. Introductions, conversations, plans, entitlements, and notification state are group-aware or group-owned.

## Referential Behavior

| Relationship | Delete Behavior |
|---|---|
| Member to verification cases | Restrict physical deletion; member deletion soft-deletes public surfaces. |
| Member to groups | Active membership is closed; group eligibility recomputed. |
| Group to introductions | Preserve for audit; active introductions are removed or expired. |
| Group to conversations | Preserve conversation shell; write access may close. |
| Plan to debriefs | Preserve debriefs for attendance, safety, and mutual edge audit. |
| Safety reports to evidence media | Preserve under safety retention class even if reporter deletes account, subject to legal policy. |
| Purchase to entitlements | Preserve purchase ledger; entitlement can expire or revoke. |

## Data Privacy Boundaries

| Data | Storage Boundary | Access Rule |
|---|---|---|
| Raw government ID and liveness media | Persona only | Never stored in [APPNAME] database or S3. |
| Verification status | `members`, `verification_cases` | Member, group eligibility, trust/safety staff. |
| Group profile | `groups`, `group_profiles`, `vouch_blurbs`, `media_assets` | Visible only after all active members approve publication. |
| Launchpad readiness | `group_readiness_snapshots` | Current group members; contains blockers/actions only, not cards or ranking scores. |
| Availability mesh | `group_availability_snapshots` | Group members and matching/planning services; contains group-level overlap only, not raw calendar content. |
| Chat messages | `messages` | Conversation participants and authorized safety reviewers. |
| Report evidence | `media_assets` with safety retention | Reporter and safety reviewers; not shown to reported users by default. |
| Debrief interest | `debrief_interests` | Private to submitter until mutual edge is created. |
| Mutual edge | `mutual_edges` | Only the two involved members. |
| Payment state | `purchases`, `entitlement_grants` | Purchaser, current group capability checks, support. |

## Non-Obvious Constraints

1. `introductions` has a constraint that exactly one of `target_group_id` or `target_plan_id` is set. This supports quartet and social-pod formats without introducing member-level discovery.
2. `notification_intents.source_event_id` is non-null. This makes generic re-engagement pushes structurally impossible from the notification ledger.
3. `conversation_participants.group_id` is required. Even breakout participants retain group context for safety and audit.
4. `introduction_sets.baseline_size` and `entitlement_extra_size` are stored separately. This audits that paid stack expansion never reduces the free baseline.
5. `debrief_interests.visibility_status` defaults to `private`; only mutual evaluation can set `mutual_revealed`.
6. `groups.distribution_floor_version` ties matching results to the currently approved free distribution floor. Any paid-matching change must preserve or increase that floor.
7. `idempotency_keys` makes mutating API retries explicit and detects key reuse with mismatched request bodies.
8. `provider_webhook_events` records signature-verified provider event IDs before provider-specific state transitions.
9. `group_readiness_snapshots.source_event_id` is required so Launchpad, realtime, and push updates are derived from persisted group-state changes, not ad hoc engagement jobs.
10. `group_availability_snapshots` stores group-level overlap windows only. Raw calendar event content remains prohibited in P0.
